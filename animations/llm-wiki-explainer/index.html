How an LLM Wiki works

Plain RAG rediscovers knowledge from raw chunks on every question. An LLM Wiki has the model compile each source into a persistent, interlinked set of markdown pages, keep those pages current, and answer from them. Good answers go back into the wiki, so it compounds.

The three operations

  1. Ingest. You add a source. The LLM reads it, writes a summary page, updates the entity and concept pages it affects, creates missing ones, flags contradictions, and updates index.md and log.md. One source can touch 10 to 15 pages.
  2. Query. The LLM reads the index first, then packs the relevant wiki pages, plus raw sources where it needs detail, into the context window and answers with citations. A good answer is filed back as a new page.
  3. Lint. Now and then the LLM health-checks the wiki: orphan pages, stale claims, missing cross-references, concepts without a page.

The three layers

RAW SOURCES

Your curated documents. Immutable: the LLM reads them and never edits them.

WIKI

Markdown pages the LLM writes and owns: sources, entities, concepts, syntheses, plus an index and a log.

SCHEMA

A rulebook such as CLAUDE.md that tells the LLM how to ingest, answer and maintain the wiki.
