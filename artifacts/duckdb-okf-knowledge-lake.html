A DuckDB data lake + Open Knowledge Format
as a knowledge graph for AI agents

Two planes, one brain. A DuckDB lake holds the facts — Parquet files queried live with SQL, no server to run. Open Knowledge Format (OKF) holds the meaning — a curated directory of markdown concepts whose links are the knowledge graph. Agents read OKF for context and query DuckDB for data. 3

Markdown links connect revenue → fct_orders → dim_customer. The agent walks the graph to learn which tables to join and that “active” means an order in the trailing 90 days.

4

Resolve the binding OKF DuckDB

Each concept's resource: field names a concrete DuckDB view (analytics.fct_orders). Meaning maps to a queryable object.

5

Generate & run SQL DuckDB

The agent emits SQL that reads Parquet in place via views. DuckDB executes the OLAP scan in-process — seconds, no warehouse.

6

Answer with provenance agent

The number comes from DuckDB; the definition and caveats come from OKF. The agent cites both — and the trust caveat in the runbook is part of the answer.

Key idea:  OKF answers “what does this mean?”  ·  DuckDB answers “what are the numbers?” 

An OKF concept is just a markdown file with YAML frontmatter. The only required field is type. Links to other concepts form the graph; the resource field binds the concept to a DuckDB object.

# wiki/concepts/revenue.md
---
type: metric
title: Revenue (recognized)
description: Net recognized revenue, EUR, excluding refunds.
resource: duckdb://analytics.fct_orders   # ← binding to the data plane
tags: [finance, kpi, certified]
timestamp: 2026-06-20
---

# Revenue (recognized)

Sum of `amount_eur` on **[fct_orders](fct_orders.md)** where
`status = 'captured'`, joined to **[dim_customer](dim_customer.md)**
for region. An order counts toward an **[active customer](active-customer.md)**
when placed in the trailing 90 days.

> ⚠️ Runbook: pre-2025 rows use gross amounts — see
> **[revenue-migration](runbooks/revenue-migration.md)**. Trust = medium before 2025-01.
The links  [fct_orders] ,  [dim_customer] ,  [active customer]  are the edges of the knowledge graph

Notice: this is exactly the pattern this repository already uses — typed markdown pages, frontmatter, wikilinks. An LLM wiki is an OKF knowledge layer; pointing each concept's resource: at a DuckDB view is all it takes to make the lake agent-ready.

This diagram has four bands, bottom to top: sources feed storage (Parquet in object storage); the brain splits into a DuckDB data plane and an OKF knowledge plane; and agents sit on top.

Why two planes?

Facts change every second and live in DuckDB. Meaning changes rarely and is curated by humans in OKF. Keeping them separate — but bound by the resource: field — is what makes the lake safe for an agent to reason over.
